## 시뮬레이션이 두 가지를 드러냈다

### 1. 예정된 비트가 발동하지 않았다

마일스톤(턴 9·18·27·36)과 진로 선언(턴 19)은 **추첨이 아니라 예정된 비트**인데, 시뮬레이션이 3턴 주기 가중 추첨으로만 이벤트를 뽑고 있었다. 턴 19는 3의 배수가 아니라 **진로 선언이 한 번도 발동하지 않았다.**

`milestone`·`path`·`condition` 카테고리를 매 턴 자격 확인하도록 분리했다. 결과:

```
고유 이벤트 분포: { "milestone": 4, "path": 1, "opp": 7, "world": 3, "cond": 1 }
```

### 2. 상태이상에 탈출 경로가 구현돼 있지 않았다

슬럼프 진입이 7런에 **23회**(런당 3.3회)로 비정상적으로 높았다. 휴식 임계를 65 → 45로 낮춰도 23 → 22로 거의 변하지 않아 **휴리스틱이 아니라 구현 문제**임이 드러났다.

원인: 설계에는 부진·부상·평판 추락의 탈출 조건이 명시돼 있는데 `turn.gd` 가 **진입만 구현하고 탈출을 구현하지 않았다.** 부진이 영구 지속되면서 `slump_light_turns` 카운터가 계속 올라 슬럼프를 반복 유발했다.

`SaRisk.exiting_conditions()` 를 구현했다.

| 상태 | 탈출 |
|---|---|
| 부진 | 휴식 2턴 연속 **또는** 대성공 1회 |
| 슬럼프 | 휴식 3턴 연속 (온천·NPC 경로는 이벤트가 처리) |
| 부상 | 3턴 경과 |
| 평판 추락 | 평판 15 회복 |
| 번아웃 | 강제 2턴 소모 후 자동 |
| **낙제** | **없음 — 설계상 의도. 이번 런의 band 4 를 영구 잠근다** |

해제를 진입보다 먼저 처리해 같은 턴에 나갔다 들어오지 않게 했다.

**결과: 슬럼프 진입 23 → 9회** (런당 1.3회).

회귀 테스트를 붙였다. 상태 6종의 탈출 조건과, **조건 미충족 시 나가지 않는 것**, 낙제에 탈출이 없다는 것까지 검사한다.
