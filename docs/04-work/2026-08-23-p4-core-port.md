## 계획에서 조정한 것

계획의 4.3b 는 *"옛 월간 루프를 GDScript 로 얇게 재구현해 `pnpm legacy:balance` 와 같은 판정을 재현"* 이었다. 이를 **더 저렴하면서 같은 보증을 주는 방식**으로 바꿨다.

| | 계획 | 실제 |
|---|---|---|
| 방식 | 옛 루프를 GDScript 로 재구현해 재시뮬레이션 | legacy 엔진으로 최종 상태를 덤프하고, **이식된 판정 로직**을 그 상태에 대고 검증 |
| 검증 대상 | 4.3c 에서 버려질 시뮬레이터 | **실제로 살아남는 코드** (요건 평가 + 엔딩 판정) |
| 버려질 작업 | 옛 월간 루프 재구현 전부 | 없음 |

목적("하네스 실패가 하네스 버그인지 설계 변경인지 판별")은 그대로 달성된다. 판정 로직이 legacy 와 등가임이 증명됐으므로, 이후 루트가 실패하면 그것은 설계 변경 때문이다.

## 4.3a — 콘텐츠 이식

legacy TypeScript 빌드에서 추출했다.

| 파일 | 내용 |
|---|---|
| `data/legacy-actions.json` | 액션 19종 |
| `data/legacy-endings.json` | 엔딩 30종, 요건 84개 |
| `data/legacy-labels.json` | 스탯 14종·카테고리 라벨 |
| `data/legacy-route-plans.json` | 30루트 × 12개월 × 4주 = **1,440 주차** |

요건 타입 5종: `stat`, `resource`(방향 `at-most` 지원), `flag`, `flag-sum`, `average`.

## 4.3b — 등가성 검증

### 이식한 코어

| 파일 | 역할 |
|---|---|
| `packages/product-core/src/domain/ending_requirements.gd` | 요건 5종 평가. 코어는 JSON 을 모르므로 Dictionary 만 받는다 |
| `packages/product-core/src/domain/ending_judgement.gd` | `judge_legacy`(등가성 검증 전용) + `judge`(새 특이도 판정) |

### 결과

```
등가성 비교: 179 조합, 불일치 0
LEGACY EQUIVALENCE PASS
```

210 조합 중 legacy 에서 차단되지 않은 **179 조합 전부에서 GDScript 판정이 TypeScript 와 동일**했다.

### ground truth 가 드러낸 사실

30루트를 7시드로 돌린 결과:

| 지표 | 값 |
|---|---:|
| 시드 1 에서 명명 엔딩 도달 | **30 / 30** |
| **7시드 전부에서 안정** | **15 / 30** |
| legacy 에서 차단된 조합 | 31 / 210 |

**기존 하네스는 `createNewRun(1)` 로 시드 1 만 검사한다.** 그래서 PASS 가 나왔다. 시드를 넓히면 절반이 흔들린다.

불안정 루트 15종: `court-scribe`, `wanderer`, `observatory-director`, `star-priest`, `spellwright`, `healer`, `garden-architect`, `travel-writer`, `academy-professor`, `city-councilor`, `inventor`, `guardian-guide`, `etiquette-master`, `workshop-founder`, `archive-detective`.

이것이 불변식 7(7개 고정 시드 스윕)이 필요한 이유이고, 이제 근거가 저장소 안에 데이터로 있다.

### 섀도잉 회귀 증명

모든 엔딩 요건을 넉넉히 넘기는 만렙 상태를 만들어 두 판정을 비교했다.

| | 결과 | 특이도 |
|---|---|---:|
| 자격 엔딩 | **29 / 30** | — |
| 구 판정 (`priority ?? index`) | `court-scribe` | **12.0** |
| 새 판정 (특이도 점수) | `academy-professor` | **29.5** |

구 판정은 요건이 낮은데 `priority: 30` 이 박힌 엔딩으로 수렴한다. 새 판정은 요건이 실제로 가장 높은 엔딩을 고른다. 이 비교는 회귀 테스트로 고정돼 있어, 누가 우선순위 기반 판정을 되살리면 실패한다.

## 남은 것 — 4.3c · 4.3d

**아직 하지 않았다.** 이 기록은 4.3a·4.3b 까지다.

| 단계 | 내용 | 선행 조건 |
|---|---|---|
| 4.3c | 주 단위 루프, 자원·리스크, 상태이상 6종, NPC 호감, 선택지 이벤트 해결, 마일스톤 구현 → 30 루트 재저작 | 액션 38종·이벤트 106종 콘텐츠(P6)가 있어야 루트를 재저작할 수 있다 |
| 4.3d | `legacy/` 삭제 | 4.3c 통과 후 |

`legacy/` 는 4.3d 까지 삭제하지 않는다. 4.3c 에서 루트가 실패할 때 그것이 설계 변경 때문임을 판별하는 기준이 이 등가성이다.

## 사용한 명령

```bash
export GODOT_BIN=/tmp/godot-4.7.1-stable-macos/Godot.app/Contents/MacOS/Godot
"$GODOT_BIN" --headless --path . --import --quit          # class_name 캐시 갱신. 새 코어 파일 추가 후 필수
pnpm godot:core
pnpm godot:equivalence
pnpm godot:arch
```

> **주의**: 새 `class_name` 을 추가한 직후에는 import 를 먼저 돌려야 한다.
> 안 그러면 `Identifier "..." not declared` 파스 에러가 나는데 **Godot 은 그래도 exit 0 을 낸다.**
> 실제로 이 단계에서 겪었고, 로그 게이트가 없었으면 초록으로 통과했을 상황이다.
