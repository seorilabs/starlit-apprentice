## 회차 덱 — 재플레이 서사 차별화

설계의 장치를 구현했다. 기회 이벤트 24종을 **서로 겹치지 않는 3개 덱(각 8종)**으로
나누고, 회차마다 다른 덱만 연다. 연속 두 회차는 기회 이벤트가 **하나도 겹치지 않는다.**

- `SaResources.new_state(seed, deck)` 가 `state.deck` 을 심는다
- `SaEventResolution.eligible()` 이 덱이 다른 이벤트를 아예 배제한다
- **코어는 회차 수를 모른다.** 호출자가 유도해 주입한다 — 시간도 영속화도 코어 밖이다

회차 수 영속화는 별빛 기록(메타 진행)에서 붙는다. 지금은 세션 안에서만 센다.

시뮬레이션은 시드마다 덱을 돌려 24종 전부를 검증 범위에 넣는다.
불변식 2개를 걸었다 — 덱이 다른 이벤트가 뜨면 실패, 기회 커버리지 70% 미만이면 실패.

## 린트가 스스로 낡지 않게 만들었다

효과 키 오타(`stats2`)를 저작 중에 냈다. 코어는 모르는 키를 **조용히 무시**하므로
효과가 통째로 날아가도 에러가 나지 않는다. 검사를 붙였는데, 이번엔 **린트가 틀렸다** —
허용 목록에 `turn_skip` 을 빠뜨려 멀쩡한 콘텐츠 3건을 오탐했다.

손으로 관리하는 어휘 목록은 반드시 낡고, 낡은 린트는 통과 표시를 내면서 아무것도
보장하지 않는다. 그래서 **코어 소스에서 어휘를 직접 추출**하게 바꿨다.

| 어휘 | 추출 대상 |
|---|---|
| 이벤트 요건 타입 | `event_requirements.gd` 의 `match` case 라벨 |
| 엔딩 요건 타입 | `ending_requirements.gd` 의 `const TYPE_*` |
| 비용·효과 키 | `resolve_event_choice.gd` 의 `cost.get(...)` / `effects.get(...)` |
| 스탯 | `stat_keys.gd` 의 `ALL` 배열 리터럴 안쪽 |

마지막 항목은 주의가 필요했다. 배열 뒤의 `const REPUTATION` 까지 긁으면 평판이
스탯으로 섞인다 — **평판은 스탯 배열이 아니다.** 리터럴 안쪽만 보게 경계를 잡았다.

추출이 실패하면 그 자체를 에러로 낸다. 코어의 case 라벨 하나를 바꿔 주입해 보니
린트가 13건을 잡았다 — 어휘가 어긋나면 조용히 통과하지 않는다.

## `turn_skip` 은 이미 구현돼 있었다

린트가 `turn_skip` 을 모르는 키로 신고했을 때, 설계 팩에 명시된 기능이라
"구현 누락"으로 판단할 뻔했다. 코어를 직접 읽어 보니 `apply()` 에 이미 있었다.
고쳐야 할 것은 콘텐츠도 코어도 아니라 린트였다.
