## 이벤트 24종

세라·이든·하린·모란·구 노인·윤 각 4종. 기존 6종과 합쳐 **NPC 풀 30종**이 됐다.
전체 이벤트 23 → **47종**, 이벤트 한국어 저작량 **17,347자**.

각 체인은 하나의 호를 그린다 — 세라는 자기 실패를 보여 주고 결국 관측표를 넘기고,
이든은 라이벌에서 동맹과 경쟁 양쪽으로 갈리고, 모란은 값을 매기다 값을 받지 않는다.
선택지에는 `once_per_run` 플래그가 붙어 엔딩 요건과 연결된다.

## 린트가 잡은 것 3건

**요건 타입 오타는 조용히 영구 거짓이 된다.** `SaEventRequirements.is_satisfied` 는
모르는 타입에 `false` 를 돌려주고 에러를 내지 않는다. 저작 중 `{"type":"reputation"}` 을
썼는데 코어는 `{"type":"resource","resource":"reputation"}` 만 안다. 그 선택지는
영원히 회색으로 남았을 것이다.

`check_requirement_types()` 를 추가했다. **이벤트와 엔딩은 평가기가 다르고 어휘도 다르다** —
이벤트는 `declared_path`, 엔딩은 `declared` 를 쓴다. 처음에 한 어휘로 검사했다가
엔딩 12개를 오탐했고, 파일별 어휘로 나눠 고쳤다. 주입으로 양방향 확인했다.

| 검사 | 잡는 것 |
|---|---|
| 요건 타입 어휘 | 조용히 영구 거짓이 되는 오타 |
| NPC 참조 무결성 | 없는 NPC 를 가리켜 호감이 영원히 0 인 게이트 |
| 체인 공백 경고 | 임계값에 이벤트가 없어 투자에 보상이 없는 구간 |
| `locked_reason` 누락 | 사유 없이 잠긴 선택지 (기존 검사, 9건 적발) |

## 시뮬레이션이 검증하던 게임이 실제 게임과 달랐다

NPC 이벤트가 **런당 1건**만 발동했다. 30종을 저작했는데 검증되는 건 1종이었다.

두 가지가 어긋나 있었다.

1. **시뮬레이션이 `함께` 를 한 번도 쓰지 않았다.** 호감의 주 채널인데 라이더(+2)만
   작동해 임계값에 닿지 못했다.
2. **`npc` 카테고리 처리가 달랐다.** `run_controller` 는 예정 비트로 다루는데
   시뮬레이션은 1/3 추첨 풀에 넣어 다른 카테고리와 경쟁시켰다.

`together_candidate()` 를 `SaTurn` 으로 올려 UI 와 시뮬레이션이 같은 규칙을 보게 했다.
규칙이 두 곳에 있으면 시뮬레이션이 검증하는 게임과 플레이어가 하는 게임이 갈린다.

| 지표 | 이전 | 이후 |
|---|---:|---:|
| 런당 NPC 이벤트 | 1 | 5 |
| 고유 NPC 이벤트 | 1 | 18 / 30 |
| `함께` 사용 | 0 | 48회 (7시드) |
| 최고 호감 | — | 하린 82 · 세라 74 · 구 73 |

회귀 가드 2종을 걸었다 — `함께` 사용 0회, NPC 이벤트 시드당 3회 미만이면 실패.

이든이 28 로 낮다. 담력·별감응 행동을 시뮬레이션의 대표 플레이가 잘 고르지 않는다.
이든 전용 엔딩 2종의 도달성은 `route_plans` 가 따로 보장하므로 지금 막히는 건 없지만,
기회 이벤트를 채울 때 이든 라이더가 붙은 행동을 늘려야 한다.
