# 커스텀 로딩 셸 — 크기 상한을 걷어내다

- 날짜: 2026-08-23
- 단계: P7 준비 — 아트 예산 제약 해소
- 관련: [[../02-decisions/0009-loading-shell-over-size-cap]]

## 먼저 사실관계

아트 작업 전에 예산을 계산했더니 **약 3.4MB 부족**했다. 그 과정에서 두 가지를 확인했다.

**`10초`는 내가 세운 목표가 아니라 AIT 게임 출시 체크리스트의 필수 항목이다.**
원문(SRC-001)을 직접 열어 확인했다 — "미니앱이 10초 이내에 최초 화면까지 정상적으로
열려요", 서문에 "출시하기 전에 반드시 내용을 확인하고 가이드를 지켜 주세요".

다만 **로딩 화면·인디케이터에 관한 규정은 체크리스트에 없다.** "최초 화면"이 로딩
화면을 포함하는지 원문은 답하지 않는다.

`15MB` 라는 숫자는 우리가 정한 것이 맞다. ADR-0006 이 10초 조항을 **크기 상한으로
번역한** 결과이고, 그 번역이 아트와 오디오를 서로 밀어내게 만들었다.

## 결정과 근거

크기 상한을 하드 게이트에서 걷어내고 **로딩 화면으로 조항을 만족시킨다**(ADR-0009).

`web/shell.html` — Godot 공식 웹 셸을 원본으로 브랜드 로딩 화면을 얹었다.
서리랩스 공식 `Shared Stem` 한글 심볼·진행바·퍼센티지가 **HTML/CSS 파싱만으로** 그려진다.

**실측: 41MB 번들에서 First Contentful Paint 196 ms, `domInteractive` 120 ms.**
첫 페인트는 수 KB 짜리 HTML·CSS 가 결정하며 번들 크기와 무관하다.

`onProgress` 를 퍼센티지에 이었다. 길이를 모르는 구간(wasm 컴파일)에서는 천천히
밀어 올리되 100% 에는 닿지 않는다 — 멈춘 것처럼 보이지 않게. 실패하면 한국어 안내를
띄운다. 흰 화면으로 끝나지 않는다.

## 만드는 과정에서 겪은 것

**`str.replace` 가 조용히 실패했다.** 공식 템플릿은 탭 하나로 들여쓰기하는데 앵커를
탭 둘로 잡았다. 마크업만 들어가고 CSS 는 통째로 빠진 채 export 됐고, 스크린샷에는
Godot 기본 오버레이가 우리 화면을 덮은 모습만 남았다.

원인을 추측으로 좁히지 않고 `--dump-dom` 으로 DOM 을 덤프해 확인했다 — 마크업은
있는데 스타일이 없었다. 셸을 처음부터 다시 생성하되 **모든 치환에 "앵커가 정확히
1회 발견되는가" 검증을 걸었다.** 조용한 no-op 이 이번 문제의 유일한 원인이었다.

## 게이트 재구성

`scripts/check_web_budget.sh` 의 하드 실패는 이제 넷뿐이다.

| 검사 | 근거 |
|---|---|
| 비압축 총량 > 100MB | AppsInToss 패키징 하드 리밋 |
| 커스텀 로딩 셸이 빌드에 없음 | ADR-0009 의 전제가 무너진다 |
| pck 에 한국어 폰트 없음 | cold export 가 importer 를 건너뛴다 (R2) |
| 출하 pck 구동 중 Godot 에러 | 출시 불가 |

gzip 총량과 pck 는 참고선으로 계속 출력한다. **관측을 멈추는 것이 아니라 차단을
멈추는 것이다.** 로딩 셸 검사는 주입으로 확인했다(제거 시 exit 1).

현재 실측: 총 전송량 12.29 MB · pck 2.55 MB · 비압축 40.84 MB / 100 MB.

## 닫히지 않은 것

- **"최초 화면"의 해석.** 심사자가 "플레이 가능한 화면"으로 읽으면 이 결정은 조항을
  만족시키지 못한다. 원문에 정의가 없다.
- **FCP 196 ms 는 localhost 값이다.** 실기기·실네트워크 측정이 아니다.
- **R17 은 그대로다.** 검증 중 WebGL2 가 없는 환경에서 Godot 이 즉시 실패하는 것을
  확인했다. AIT iOS WebKit 이 그 경우라면 크기와 무관하게 막힌다.

셋 다 실기기 QR 샌드박스 측정으로만 닫힌다. P9 에서 수행한다.
