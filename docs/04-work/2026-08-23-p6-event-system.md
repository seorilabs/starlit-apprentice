## 구현

| 파일 | 역할 |
|---|---|
| `src/domain/event_requirements.gd` | 이벤트 요건 8종 (stat·resource·affinity·npc_met·flag·turn_range·condition·declared_path) |
| `src/use_cases/resolve_event_choice.gd` | 후보 선별·가중 추첨·선택지 가용성·판정·효과 적용 |
| `data/events.json` | 이벤트 10종 (목표 106) |

구 구현의 `GameEvent` 에는 **`choices` 필드 자체가 없었다.** 이벤트는 자동 적용되는 통보였고 12번 중 4번만 발동했으며 전부 성공했다.

## 시뮬레이션 (7시드 × 36턴)

```
완주 7/7 | 골드<40 경험 7 | 기력<30 경험 7
상태이상 진입: { "slump_light": 1, "slump": 6 }
이벤트 발동 78회, 고유 7종 | 잠긴 선택지 노출 35회
턴 29 이전 캡 도달: 없음
```

**잠긴 선택지가 35회 노출됐다.** 미충족 선택지를 숨기지 않고 사유와 함께 보여주는 설계가 실제로 동작한다는 뜻이다. 시뮬레이션은 잠긴 선택지에 사유가 없으면 실패한다.

## 콘텐츠 린트 확장

이벤트 규칙 5종을 추가하고 주입 검증했다.

| 주입 | 결과 |
|---|---|
| 선택지 1개로 축소 | exit=1 |
| 요건은 있는데 `locked_reason` 제거 | exit=1 |
| 성공/실패 결과문 중복 | exit=1 |
| 판정 있는데 분기 1개만 | exit=1 |
| `result_text` 가 `body` 와 동일 | exit=1 |

**이 검증이 내 저작 결함을 잡았다.** world 이벤트 3종이 `body` 를 `result_text` 로 재사용하고 있었다 — 설계가 비판한 "본문 4종이 12회 반복" 을 작은 규모로 재현한 셈이다. 규칙을 추가하고 세 문장을 다시 썼다.

## 겪은 것 — 파이프라인이 승인된 자산을 덮어썼다

아이콘 배치를 `--only` 없이 돌렸더니 **이미 승인된 자산까지 재생성하려 했다.** 파이프라인의 "기존 최종본 건너뛰기" 는 `<name>.png` 를 찾는데, 우리 최종본은 WebP(ADR-0008)라 판정이 항상 빗나간다.

중단 시점에 `raw/` 원본 3개가 새 이미지로 덮여 최종본과 어긋났다. git 에서 복원했고, `assets/art/README.md` 에 `--only` 필수를 경고로 남겼다.

**기회 이벤트 3덱 분할은 스키마에 `deck` 필드로 준비했으나 추첨 로직에는 아직 반영하지 않았다.** 덱당 8종이 모여야 의미가 생긴다.

마일스톤·진로 선언·엔딩 재저작·30루트 재저작은 이벤트 저작이 더 진행돼야 한다.
