## 리뷰와 플레이어 문제 종합

- 육성 시뮬의 정의 자체가 **"일정 간격으로 스케줄을 짜면 이벤트가 발동하고 파라미터가 변하며, 엔딩을 보는 것이 목표"**다(SRC-010). 스케줄 → 파라미터 → 엔딩이 장르 계약이다.
- **"따뜻한 분위기에도 불구하고 결국 전부 파라미터로 결정된다는 점에서 다소 무자비하다"**(SRC-010). 파라미터의 무자비함이 장르의 특징이지, 결함이 아니다.
- **"파라미터가 바닥나거나 편중되어 발생하는 엔딩이 정규 엔딩보다 인기 있는 경우가 많다"**(SRC-010). 실패 엔딩은 벌칙이 아니라 **콘텐츠**다.

## AppsInToss 플랫폼 계약 (SRC-001 원문 기준)

미니앱 게임은 다음을 **강제**받는다. 설계·QA 인수 조건에 그대로 편입한다.

**접속·사운드**
- 미니앱이 **10초 이내**에 최초 화면까지 정상적으로 열려요. → **W2**
- 배경음·효과음·햅틱이 적용돼 있어요. 사운드가 있으면 **사용자가 직접 On/Off 설정**할 수 있어요.
- 백그라운드 전환 시 사운드 **즉시 종료**, 복귀 시 **정상 재생**.

**UX·내비게이션**
- Safe Area를 침범하지 않아요. 우측 상단 닫기 버튼이 정상 동작해요.
- 진입 직후 바텀시트가 자동으로 나타나지 않아요.
- **인앱 광고는 인트로/로딩/컷신/팝업 모달 등 일시적인 화면에 노출되지 않아요.**

**보안·안정성**
- **외부에서 전달받은 코드를 실행하는 기능은 사용할 수 없어요.** → 계획 R1(Godot 웹 로더 eval shim 자동 반려)이 **정책 조항으로 확인**됐다.
- SSR 사용 불가. WebSocket은 `wss://`만. API는 HTTPS만.

**서비스 이용 동작**
- 인게임 화면은 **풀스크린**. 세로 모드가 의도대로 동작.
- **운영체제의 뒤로가기 제스처는 사용할 수 없어요.**
- 인터랙션 반응이 **2초 이상 지연되지 않아요.**
- 미니앱 종료 시 **확인 모달**이 노출돼요.
- 사용자 식별키로 플레이 기록이 유지돼요(종료 후 재접속 포함).

**인앱 광고** — 정책상 **허용된다.**
- 광고 재생 시 음악 일시정지, 종료 후 재개.
- **사용자가 예상하기 어려운 순간에 노출하지 않아요.**
- **광고는 사전에 로딩돼 있어요.**
- 리워드 광고를 끝까지 시청하면 보상이 정상 지급돼요.
- 배너 광고는 **상단 또는 하단에만** 위치해요.

## 게임물 등급분류 경로 (SRC-002, SRC-003 기준) — 계획 미결 항목 E1 해소

두 경로가 있다.

1. **게임물관리위원회 직접 등급분류 신청** — 게임위 공식 홈페이지 `등급분류신청` 메뉴. **심의 약 10~15일**, 완료 시 `등급분류증명서` 발급.
2. **자체등급분류 게임물** — 앱스토어(IARC)를 통해 연령등급을 받은 게임물을 유통하는 경우, AppsInToss 콘솔에 **자체등급분류 게임물 정보를 추가 입력**한다.

> **AppsInToss는 등급분류 주체가 아니다.** 자체등급분류 정보를 입력하는 창구다.

**미작성 시 제재**: 등급분류를 받지 않은 **등급미필 게임물로 간주**되어 시정권고, 수사의뢰 또는 행정처분의뢰 등 행정조치로 이어질 수 있다(SRC-003).

**따라오는 순서 제약 (계획에 없던 것)**
```
Google Play / App Store IARC 연령등급 취득
        ↓
AppsInToss 콘솔에 자체등급분류 게임물 정보 입력
        ↓
AppsInToss 출시
```
즉 **AIT 출시는 두 스토어의 IARC 등급 이후로 순서가 고정된다.** 3마켓 "동시" 출시는 AIT가 뒤따르는 형태가 된다.

## 부록 A. Godot Web 로드 예산 실측 (2026-08-23)

W2/H4/D3를 콘텐츠 저작 전에 판정하기 위해, 이미 출시된 org Godot 게임의 실제 Web export를 계측했다.

| 산출물 | raw | gzip |
|---|---:|---:|
| lizard-tycoon `index.wasm` | 35.9 MB | **8.9 MB** |
| lizard-tycoon `index.pck` | 5.7 MB | **3.8 MB** |
| spiritgate-defenders `index.wasm` | 37.6 MB | **9.6 MB** |
| spiritgate-defenders `index.pck` | 44.4 MB | **42.4 MB** |

**판정: Godot Web은 AppsInToss 10초 제약 안에서 성립한다. 단 pck 예산을 지켜야 한다.**

Godot 공식 문서(SRC-012)와 실측이 일치한다 — 문서는 `.wasm`이 *"gzip으로 원본의 약 1/4까지 압축된다"*고 명시하고, 실측 35.9 MB → 8.9 MB가 정확히 그 비율이다.

- **Godot 4 Web 엔진 자체가 gzip 약 9 MB의 고정 바닥값**이다. 어떤 최적화로도 이 아래로 내려가지 않는다.
- **lizard-tycoon은 총 gzip 약 12.7 MB로 이미 AppsInToss에 출시돼 있다.** 이것이 존재 증명이다 — Godot Web + AIT 조합 자체는 반려 사유가 아니다(반려됐던 `20260814-13`은 크기가 아니라 eval shim 때문이었다).
- **spiritgate의 pck 44.4 MB는 gzip이 거의 듣지 않는다(42.4 MB).** 텍스처가 이미 압축돼 있어서다. 즉 **로드 시간을 죽이는 것은 코드가 아니라 텍스처다.**

**따라오는 에셋 예산 (설계 제약으로 승격)**

| 항목 | 예산 |
|---|---:|
| 엔진 wasm (고정) | ~9 MB gzip |
| pck 상한 | **≤ 6 MB gzip** |
| **총 전송량 목표** | **≤ 15 MB gzip** |

플랫 일러스트 + 텍스트 중심 게임이라 이 예산은 현실적이다. 다만 다음을 지켜야 한다.
- 엔딩 일러스트 30종을 전부 대형 원본으로 넣지 않는다. 해상도 상한을 정하고 필요 시 공통 프레임 + 중앙 일러스트 구성으로 분해한다.
- VRAM 텍스처 압축(ETC2/ASTC)은 모바일 네이티브 빌드에 유리하지만 **Web pck에서는 gzip 효율을 떨어뜨린다.** Web preset의 텍스처 처리 방식을 네이티브와 분리해 결정하고, 각 조합의 pck 크기를 실측해 고른다.
**추가 레버 (SRC-012)**
- *"사용하지 않는 기능을 끈 최적화 export template을 컴파일하면 WebAssembly 페이로드 크기를 상당히 줄일 수 있다."* → 9 MB 바닥값을 낮출 수 있는 유일한 수단. P3 이후 필요하면 적용한다.
- 서버 압축은 **gzip보다 Brotli 권장**. `.ait`는 Toss 호스트가 서빙하므로 압축 방식이 우리 통제 밖일 수 있다 — 실측으로 확인한다.
- `thread_support=false`는 Godot 4.3부터 **기본값**이고 COOP/COEP 헤더 요구를 없애 *"전반적으로 더 호환된다"*. 계획 B5의 선택과 일치한다.

- **P3(Godot 골격) 완료 직후, 콘텐츠를 채우기 전에** 빈 프로젝트 + 폰트만으로 Web export를 뽑아 실기기 QR 샌드박스에서 최초 화면 도달 시간을 측정한다. 이때 이미 10초에 근접하면 AIT 타깃을 재검토한다.

## 부록 B. iOS WebView 렌더링 리스크 (SRC-012)

Godot 공식 문서는 *"Safari는 다른 브라우저에 없는 WebGL 2.0 지원 문제를 여럿 가지고 있다"*고 명시하고 Chromium 계열 또는 Firefox를 권장한다.

**이것이 우리에게 중요한 이유**: AppsInToss iOS 클라이언트는 WKWebView이고, WKWebView는 Safari와 같은 WebKit 엔진을 쓴다. 즉 **AIT iOS 경로는 Godot이 "권장하지 않는다"고 적어 둔 바로 그 환경**이다.

- 완화 근거: lizard-tycoon이 Godot Web으로 AppsInToss에 이미 출시돼 있다 → 치명적 차단은 아니다.
- 그럼에도 **iOS 실기기 QR 샌드박스 검증을 Android와 별도의 인수 항목으로 분리**한다. Android에서 통과한 것이 iOS 통과를 의미하지 않는다.
- 렌더러는 `mobile`(OpenGL ES 3 / WebGL 2)을 쓰되, iOS WebView에서 렌더 이상이 확인되면 `gl_compatibility` 폴백을 검토한다.

**신규 리스크 R17**: AIT iOS WebKit에서 Godot 렌더 이상. 대응 = P3 직후 실기기 선검증(R16 측정과 동시에 수행), iOS/Android 인수 분리.
