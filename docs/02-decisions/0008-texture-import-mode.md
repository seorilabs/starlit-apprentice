# ADR-0008 아트는 WebP 로 저장하고 텍스처 import 를 Lossy 로 고정한다

- 상태: `accepted`
- 날짜: 2026-08-23

## 맥락
아트 12종(캐릭터 3 · NPC 6 · 배경 3)을 처음 넣자 pck 가 gzip **1.47 → 4.68 MB** 로 뛰었다. 152종 계획의 8% 만 넣었는데 예산 6 MB 의 78% 를 썼다. 이대로면 계획된 매니페스트를 담을 수 없다.

원인을 두 단계로 좁혔다.

**1단계 — PNG 원본이 무겁다.** 배경 1장이 약 1 MB. 실측:

| 자산 | PNG | WebP q88 | 무손실 WebP |
|---|---:|---:|---:|
| `bg_tower` 768×1376 | 971 KB | **92 KB** | 700 KB |
| `apprentice` 512×512 | 162 KB | **26 KB** | 105 KB |

평면 벡터 아트는 WebP 에서 약 **9.3배** 작다.

**2단계 — Godot 이 그 압축을 버린다.** 소스를 WebP 로 바꿔도 pck 가 줄지 않았다. `.godot/imported` 를 열어 보니 Godot 이 원본을 자체 `.ctex` 로 **재인코딩**하고 있었다.

| | `.ctex` 합계 |
|---|---:|
| 기본 import (`compress/mode=0`) | **2.14 MB** |
| Lossy (`compress/mode=1`, `lossy_quality=0.9`) | **0.53 MB** |

WebP 소스 0.48 MB 가 기본 설정에서는 2.14 MB 로 부풀었다. 소스 포맷만 바꾸는 것으로는 아무 효과가 없다.

## 결정
1. 아트 최종본은 **WebP q88** 로 저장한다(`assets/art/*.webp`). 원본 PNG 는 `raw/` 에 남긴다.
2. 아트의 `.import` 는 **`compress/mode=1`(Lossy), `compress/lossy_quality=0.9`, `mipmaps/generate=false`** 로 고정한다.
3. `project.godot` 의 `[importer_defaults] texture` 에 같은 값을 넣어 신규 자산이 자동으로 따르게 한다.
4. `assets/art/raw/`, `assets/art/style/` 에 `.gdignore` 를 두어 Godot 이 아예 import 하지 않게 한다.
5. QA 콘택트시트는 재생성 가능한 산출물이라 저장소에서 제외한다.

## 근거
결과: pck gzip **4.68 → 2.00 MB**, 총 전송량 **14.43 → 11.75 MB**.

lossy 0.9 에서 눈에 띄는 열화가 없다. 굵은 아웃라인과 6색 평면 음영이라 손실 압축에 유리하고, 어두운 배경과 밝은 배경 양쪽에서 콘택트시트로 확인했다.

## 결과
152종 예산 재추정 (lossy 실측 기반):

| 항목 | 수량 | 개당 | 소계 |
|---|---:|---:|---:|
| 배경 | 8 | 92 KB | 0.72 MB |
| 엔딩 일러스트 | 30 | 31 KB | 0.90 MB |
| 이벤트 일러스트 | 24 | 31 KB | 0.72 MB |
| 캐릭터·NPC | 36 | 21 KB | 0.72 MB |
| 아이콘·토큰 | 53 | 5 KB | 0.27 MB |
| **아트 소계** | **151** | | **3.32 MB** |
| 폰트 | 1 | | 1.46 MB |
| **합계** | | | **4.79 MB / 예산 6.00 MB** |

**계획된 매니페스트가 예산 안에 들어온다.** 이 조치가 없었으면 152종은 물리적으로 불가능했다.
