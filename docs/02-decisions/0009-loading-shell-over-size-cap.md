# ADR-0009 크기 상한 대신 로딩 화면으로 10초 조항을 만족시킨다

- 상태: `accepted`
- 날짜: 2026-08-23
- 대체: [ADR-0006](0006-pck-budget.md) 의 "pck 6MB 하드 상한 · 총 15MB 목표" 부분

## 맥락

AppsInToss 게임 출시 체크리스트(SRC-001, `developers-apps-in-toss.toss.im/checklist/app-game.md`)는
**"미니앱이 10초 이내에 최초 화면까지 정상적으로 열려요"** 를 필수 항목으로 둔다.
서문이 "출시하기 전에 반드시 내용을 확인하고 가이드를 지켜 주세요" 라고 명시한다.

ADR-0006 은 이 조항을 **번들 크기 상한**으로 번역했다 — pck gzip 6MB, 총 15MB.
그 결과 아트와 오디오가 서로를 밀어내는 구조가 됐다.

| 항목 | gzip |
|---|---:|
| `index.wasm` (Godot 엔진, 고정) | 9.64 MB |
| `index.pck` (콘텐츠) | 2.55 MB |
| **총 전송량** | **12.29 MB / 15 MB** |

여유 2.71MB 에 엔딩 일러스트 30종(~1.2MB) · 이벤트 일러스트 24종(~1.85MB) ·
BGM 3곡(~3.1MB) 이 들어가야 했다. **약 3.4MB 부족**했다.

## 결정

**크기 상한을 하드 게이트에서 걷어내고, 로딩 화면으로 조항을 만족시킨다.**

`web/shell.html` — Godot 공식 웹 셸을 원본으로 한 커스텀 셸.

- 브랜드 로딩 화면(제목 · 부제 · 진행바 · 퍼센티지)이 **HTML/CSS 파싱만으로** 그려진다.
  wasm 다운로드도 컴파일도 기다리지 않는다.
- `onProgress` 를 퍼센티지에 잇는다. 길이를 모르는 구간(wasm 컴파일)에서는
  천천히 밀어 올리되 100% 에는 닿지 않는다 — 멈춘 것처럼 보이지 않게.
- 실패 시 한국어 안내를 띄운다. 흰 화면으로 끝나지 않는다.

## 근거

로컬 실측 — 41MB 번들에서 **First Contentful Paint 196ms**, `domInteractive` 120ms.
첫 페인트는 수 KB 짜리 HTML·CSS 가 결정하며 **번들 크기와 무관하다.**

Godot Web 은 어차피 wasm 컴파일 시간이 다운로드만큼 지배적이라, 크기를 깎아도
최초 화면 도달 시간이 비례해 줄지 않는다.

## 남는 하드 게이트

`scripts/check_web_budget.sh` 는 다음만 실패시킨다.

| 검사 | 근거 |
|---|---|
| 비압축 총량 > 100MB | AppsInToss 패키징 하드 리밋 |
| 커스텀 로딩 셸이 빌드에 없음 | 이 ADR 의 전제가 무너진다 |
| pck 에 한국어 폰트 없음 | cold export 가 importer 를 건너뛴다 (R2) |
| 출하 pck 구동 중 Godot 에러 | 출시 불가 |

gzip 총량과 pck 는 **참고선으로 계속 출력**하되 차단하지 않는다.
관측을 멈추는 것이 아니라 차단을 멈추는 것이다.

## 남은 위험 (R16 은 닫히지 않았다)

- **"최초 화면" 의 해석이 원문에 없다.** 브랜드 로딩 화면이 여기 해당하는지
  체크리스트는 답하지 않는다. 심사자가 "플레이 가능한 화면" 으로 읽으면 이 결정은
  조항을 만족시키지 못한다.
- **FCP 196ms 는 localhost 값이다.** 실기기·실네트워크 측정이 아니다.
- **R17 은 그대로다.** 이번 검증 중 WebGL2 가 없는 환경에서 Godot 이 즉시
  실패하는 것을 확인했다. AIT iOS WebKit 이 그 경우라면 크기와 무관하게 막힌다.

세 가지 모두 **실기기 QR 샌드박스 측정**으로만 닫힌다. P9 에서 수행한다.
